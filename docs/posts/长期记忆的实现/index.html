长期记忆的实现

2026-09-03
记忆

对于ai的记忆来说，本质上是一种数据的存储和检索。需要从过去的对话数据中，提取用户的信息，然后将其存储起来，后续可以通过检索这些信息，来实现记忆的功能。 那么对于记忆生命周期来说，其包括以下几个阶段： 入库->结构化->存储->检索->使用

记忆可以分为两种：

短期记忆

用户当前的对话session，用于本轮会话的上下文记忆。其中使用token预算作为计算指标，近期窗口，压缩总结，缩短上下文对于token使用情况。 话题topic，也是缩短上下文消耗一种手段，其通过向量等计算，可以过滤掉不相关的话题，目标也是压低上下文对于token的消耗。

模块的划分

  1. 总结模块：一种滚动，增量变更的总结模块，旧总结+新增对话=新总结.

    • 一个会话中的对话轮次可以是无限的，但是其token预算是有限的
    • 使用增量更新，避免每次总结都是从头开始

  2. 会话模块：用于存储用户当前的对话session，以及其相关的上下文信息。

    • 每个会话都有一个唯一的会话id，用于标识该会话
    • 对外提供添加和读取的接口 让客户端可以方便的调用，客户端不在需要管理会话的上下文信息

  3. 话题路由模块：用于根据用户的对话话题，提取不同的上下文信息。

    • 依据用户的对话话题转变，提取不同的上下文信息和清空旧总结

  4. 长期记忆模块： 使用Milvus数据库，用于存储用户对话向量，sqlite用来储存原始信息，Milvus只负责向量的存储和检索。sqlite负责原始数据，用户画像等结构化，原始信息的存储和检索。 长期记忆模块，需要对会话记录进行处理，从中提取信息，作为用户的长期记忆，还需要清洗数据，避免存储无效，冲突，不在作为长期记忆的信息。 除了写入，还是需要有检索功能，用于根据用户的查询，来检索用户的信息。

模块划分

  1. 数据提取模块：聚合对话记录，将用户的原始输入，使用llm提取出用户的信息，结构化
  2. 记忆检测器：当新记忆和原本的记忆出现冲突，重复等情况时，如何处理
  3. 反思模块：模拟人类回顾，用来进一步压缩
  4. 记忆排序模块：根据用户的查询，对记忆进行排序，返回最相关的记忆，其中需要对记忆的频率+近因+否定+老化等因素进行打分后排序，这尤为重要，因为检索时，需要根据用户的查询，来判断最相关的记忆。这一步也是长期记忆模块的核心，其可以影响到用户对记忆的使用。

长期记忆的检索流程： 向量 → 排序(rerank) → 去噪 → 遗忘/频次(memory_rank) → 截断(top_k)

共有模块

  1. sqlite存储：对外提供sqlite的写入和读取接口，用于存储原始数据，用户画像等结构化的数据保存和检索。
  2. milvus存储：对外提供milvus的写入和读取接口，用于存储用户对话向量，以及其相关的上下文信息

|维度|长期记忆|短期记忆| |:--|:--|:--| |生命周期|持久，夸会话|临时，会话内| |存储|sqlite+milvus|sqlite| |何时写入|批量导入|每轮对话完成 |检索方式|向量+评分|时间序+总结
