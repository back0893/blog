通过teach技能学习skills

2026-10-22
学习

如何学习新的技能？

可以参考这个skill teach技能学习skills 刚好，我可以使用这个skill来学习这个skill，让我来尝试一下。 其实 这个skill 很简单，只需要按照skill的步骤来操作即可。 还会在其目录下生成文件，来记忆学习的进度等，和上课记录一样

学习目录结构

目录 作用
MISSION.md 记录学习目标和偏好
NOTES.md 教学过程笔记
RESOURCES.md 资料清单来源
lessons/* 课程目录，每一节都有一个html文件
references/* 速查卡目录，快速查询对应节的内容
learning-records 记录学习进度

如何学习？

告诉llm 学习的目标和偏好，学习的资料 如果知道可以告知llm，不知道就 web search 来查找。 后续的课程，llm 会生成对应的学习文件，跟随llm 的提示，学习即可。

后续问题解答

skills 是否可以非常详细？

  • 不要 因为详细规定llm 会失去llm的自由度，和理解能力，对于能力约强大的llm，这种能力被剥夺越多
  • 细节干扰判断，详细的指令，但其中有漏洞或者冲突时，llm陷入纠结、甚至遵循你而放弃自己的正确判断
  • 细节本身干扰注意力，细节过多，会消耗llm的注意力和token 用来遵守细节，而不是解决问题

如何避免细节干扰？

好的模块是接口小而稳定、实现深而自由。调用方只需要知道"输入输出与契约",不必关心内部怎么实现的复杂逻辑 类似开发中，一开始先定义简单结构和实现，后续根据需求进行扩展和优化。不一开始追求完美，而是先实现基本功能，后续再根据需求进行优化。 一个skill应该时一个剧本，契约。

  • 目标：这一技能想要达到的目标，可以不详细规定每个细节
  • 硬性契约:输入必须是什么、输出必须满足哪些验收标准
  • 领域知识:模型可能不知道的约定/术语/工具用法
  • 决策准则:什么时候该用 vs 不该用、边界在哪，不规定一个固定流程
  • 约束清单:不可违反的红线(如格式、安全)，让模型自由发挥

三个落地的操作原则

写"契约 + 约束",留白给实现 —— body 里明确目标和验收标准,把"怎么达成"留给模型。 区分硬规则与软建议 —— 用极少数必须遵守的 invariant + 大量可以让模型自主选择的 open area。 随能力演进而"减重" —— 这也是你问题的点睛之笔:模型在变强,skill 应该越写越薄,而不是越写越厚。定期删掉那些模型现在"一看就懂"的废话,保留只对它有增量价值的部分。

  • 记住这句话:好的 skill 是给模型"递范围",不是给模型"装大脑"。 大脑在模型那里,skill 只负责划好边界、递上它够不到的知识 *
