记一次解码问题排查

2026-10-14
ffmpeg

单位解释：

  • dts：解码时间单位，是视频解码的时间单位，解码时间是 pts*time_base
  • pts：播放时间单位，是视频播放的时间单位 ，播放时间是 pts*time_base
  • time_base：时间基，是视频的时间单位

遇到一个问题，就是hls视频开始播放，最开始2帧会被丢弃，然后在开始播放，严格的播放器会报错。 排查问题 ffprobe 逐包看 pts / dts ffprobe -v error -select_streams v
-show_entries packet=pts,dts,duration,flags
-of csv=p=0 A000000.ts | head -12

输出的是包的顺序（也就是解码顺序），90kHz 时基，30fps 下 1 帧 = 3000：

12000,0,3000,K__ ← IDR 18000,6000,3000,___ 15000,12000,3000,___ 21000,15000,3000,___ 24000,18000,3000,___

把 DTS 那一列除以 3000，得到 0, 2, 4, 5, 6 帧：前两步各跳 2 帧，之后才是每步 1 帧。正常编码器（libx264、nvenc）是 0, 1, 2, 3…

这是因为amd的板卡解码bug导致，直接输出hls时，前2帧的dts会出现跳跃，导致解码错误。 因为这问题在hls.js或者vlc等播放器中不会出现，只有部分播放器中出错

解决

  • 添加-bf 0 参数，禁用b帧 重新编码后解决

视频转码知识

容器/编码格式

  • 容器/封装：视频文件的格式，定义数据的组织方式，定义视频，音频，字幕等数据的存储方式，可以看作为数据的存放方式，将数据按照一定的规则存放(内容盒子)，
  • 编码格式：压缩算法，容器内部数据使用的压缩算法，用来解码数据(内部盒子的数据如何压缩)

装封装/转码

  • 转封装 transmuxing：-c copy，不重新编码，秒级完成、画质零损失。用于换容器、抽音轨、按关键帧裁剪。就是重新组织数据，不改变内部盒子如何压缩
  • 转码 transcoding：解码 → 处理 → 重新编码，慢、有损。用于换 codec、改分辨率、改码率,内部盒子的数据会重新压缩

画质/体积

  • 分辨率：视频的宽度和高度，单位是像素
  • 帧率：视频每秒的帧数，每秒播放多少帧(画图)
  • 码率：每秒数据量
  • CRF：恒定质量因子,值越小越清晰,±6 约等于码率翻倍/减半
  • GOP/关键帧：每个多少帧放一个I帧
  • preset:编码速度↔压缩率权衡 帧类型是理解压缩的关键：I 帧自包含（大、可随机访问）、P 帧参考前面的帧（约一半体积）、B 帧前后都参考（压缩率最高，但带来解码乱序，即 PTS 与 DTS 不一致）

命令骨架

ffmpeg [全局选项] [输入选项] -i input [输出选项] output

选项位置极重要：-i 之前是输入选项（作用于该输入），-i 之后是输出选项（只作用于紧跟着的那个输出）。同一个 -ss 放前面是快速 seek（跳到最近关键帧，快），放后面是精确 seek（慢）

常用命令参数

  • -c: 指定编码器
  • -c copy: 不重新编码，直接复制
  • -c:v: 指定视频编码器
  • -c:a: 指定音频编码器
  • -c:s: 指定字幕编码器
  • -i: 制定输入文件
  • -an: 去掉音频流
  • -vn: 去掉视频流
  • preset：指定输出的视频质量，会影响文件的生成速度，有以下几个可用的值 ultrafast, superfast, veryfast, faster, fast, medium, slow, slower, veryslow
