# 对于并发处理
对于并发来说，如果都是无状态的，那么确实可以使用并发来处理，可以极大的加大处理效率
但是对于处理音频，文字，视频流等有序数据时，需要考虑数据的顺序问题，虽然可以将一个流的数据拆分成为多个来并发处理，但是数据的顺序不能改变
这样就是回到一个问题，我应该在并发后如何保持数据的顺序，一般的解决办法有

1. 使用seg计数，并发处理之前，先进行排序，然后并发完成后，根据seg计数来合并数据，但是这样会导致一个问题，就是排列在后先处理完成，这样需要使用缓存或者队列来保持数据的顺序
2. 使用channel来保证，但是如果在处理时并发处理，依然会有这样的问题
3. 拆分并发- segment-channel 这是对上述2个方法进行一个组合，就是先将数据拆分成成为多个大组，然后再小组之间使用channel来保证顺序，大组使用一个channel的队列顺序读取

## GO语言实现
1. 并发处理数据，无序的并发，但是内部有序写入

```
segments:=make([]chan []byte,20)
for i:=0;i<20;i++{
    segments[i]=make(chan []byte,5)
}
lock:=make(chan struct{},5)
for _,seg:=range segments{
    go func(ch chan []byte){
        lock<-struct{}{}
        defer func(){
            <-lock
            close(ch)
        }()

        //todo 处理数据
        ch <- []byte("hello")
    }(seg)
}
```
2. 顺序消费
```
for _,seg:=range segments{
    for data:=range seg{
        //todo 消费数据
    }
}
```

这种方式有着明显的优点
1. 无需显示排序-对并发数据进行一个排序或者优先队列
2. 无锁-使用channel来保证顺序，避免了锁的使用
3. 背压友好-当消费者消费慢或者排位在后的生成会被压制，不会一直生成数据

## 执行流程可视化
并发合成阶段（无序执行，但内部有序）:
┌─────────┐  ┌─────────┐  ┌─────────┐
│ seg-0   │  │ seg-1   │  │ seg-2   │  ...  ← 最多 5 个同时运行
│ goroutine│  │ goroutine│  │ goroutine│
└────┬────┘  └────┬────┘  └────┬────┘
     │            │            │
     ▼            ▼            ▼
  ch[0]        ch[1]        ch[2]       ← 每个 segment 独享 channel
     │            │            │

顺序消费阶段（严格按索引）:
     │            │            │
     ▼            ▼            ▼
  读取ch[0]    读取ch[1]    读取ch[2]    ← 必须 0 读完才能读 1
  全部帧FIFO   全部帧FIFO   全部帧FIFO
